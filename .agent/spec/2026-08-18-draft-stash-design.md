# 输入框草稿暂存区（Draft Stash）设计

日期：2026-08-18
状态：已获用户批准（待实现）

## 1. 背景与痛点

协同工作时存在一个反复出现的场景：

1. 用户正在输入框起草"下一个功能的约束提示词"（几百字，未发送）
2. agent 正在执行当前任务
3. 用户突然发现 agent 理解有偏差，必须立即发送引导消息
4. 输入框是单一缓冲区：起草内容与紧急沟通争夺同一个输入框
5. 用户被迫删除草稿 → 输入引导 → 发送 → 草稿永久丢失，重新输入

此外，输入框内容在刷新/关闭窗口后消失，用户想记录的创意想法、待办任务无处安放。

**根因**：发送动作 = 销毁输入框内容；草稿没有持久化通道。

## 2. 设计目标与原则

- **草稿绝不自动丢失**：一切内容要么发送，要么可恢复
- **零打断**：记录动作不打断思考流（快捷键完成，不弹窗）
- **可预测**：所有行为显式、可预期，不做魔法式自动判断
- **与输入框共生**：草稿是"写了但不想/不能现在发送的内容"，编辑体验与输入框一致
- **轻便**：不引入任何依赖，纯浏览器存储

## 3. 定位

一个**用户级、跨会话、浏览器存储**的草稿暂存区。草稿 = 约束提示词 / 创意想法 / 待办任务，不区分类型。它既是输入框草稿的保护伞（发送引导时草稿不丢），也是想法收集箱（随时记录、随时回填发送）。

## 4. 功能规格

### 4.1 存储

- 浏览器 `localStorage`，单 key（如 `pi-web.drafts.v1`），值 `DraftItem[]` JSON 序列化
- `DraftItem = { id: string(uuid), content: string, updatedAt: number(epoch ms) }`
- **跨会话全局存在**：任何会话、任何 cwd 下都可见（不随会话文件、不随目录）
- 生命周期：**只增不自动删**——草稿发送后条目保留，删除仅靠手动
- 容错：JSON 解析失败或结构非法时重置为空数组，不崩溃

### 4.2 快捷键（输入框聚焦时生效）

| 按键 | 行为 |
|---|---|
| **Ctrl/Cmd + S** | 新增或更新草稿 + 清空输入框，焦点留在输入框 |
| **Ctrl/Cmd + Delete**（Delete 键，非 Backspace） | 有关联：清空输入框 + 删除关联记录；无关联：仅清空输入框 |

- 一律 `preventDefault`，拦截浏览器"保存网页"（Ctrl+S）与"删除下一个词"（Ctrl+Delete）默认行为
- Ctrl+S 时输入框为空 → 无操作、无提示

**关联状态**（见 4.4）决定 Ctrl+S 是"新增"还是"更新原记录"：

| 状态 | Ctrl+S | Ctrl+Delete |
|---|---|---|
| 无关联（输入框是全新内容） | 新增一条 + 清空 | 仅清空输入框 |
| 有关联（回填自某条草稿，可能已编辑） | 更新原记录 + 清空（不新增） | 清空 + 删除原记录 |

### 4.3 列表 UI（输入框上方，毛玻璃）

- **位置**：输入框正上方、消息列表下方；与输入框视觉一体（同玻璃底色、同圆角、紧贴输入框顶部）
- **毛玻璃**：复用现有 glass 体系（`--glass-bg` + `backdrop-filter`），不新增 CSS 变量
- **显隐**：有草稿才显示，无草稿完全隐藏（零干扰）
- **条目形态**：单行显示，超宽省略号（`text-overflow: ellipsis`）
- **操作按钮**：hover 条目时浮现——
  - 左侧：**回填按钮**（⇤ 语义图标），点击回填到输入框
  - 结尾：**删除按钮**（✕），点击删除该条
  - 常态只显示文字，零噪音
- **条目本体点击无任何动作**（纯展示，杜绝误触——回填是重副作用操作，必须显式触发）
- **最大高度**：约 30% 视口高，超出内部滚动（复用现有 4px 细滚动条）
- **排序**：最近新增/最近编辑的条目在顶部（按 `updatedAt` 降序）
- **时间戳**：相对时间简写（"刚刚 / 5分钟前 / 昨天 / 3月5日"），弱化样式（小号、低对比、不抢眼）

### 4.4 回填与关联

- 点击条目左侧 ⇤ 按钮 → 内容回填输入框，**记住该条 id**（建立关联）
- **回填前保护**：若输入框已有未发送内容，先自动暂存（复用 Ctrl+S 逻辑：有关联则更新原记录、无关联则新增），再回填草稿——两边都不丢
- **关联标记**：回填后输入框显示轻量标记（如左侧小 chip「✎ 草稿 #N」+ 取消按钮），让用户明确当前处于关联态（此时 Ctrl+S 更新原记录、Ctrl+Delete 删除原记录）——没有此标记，id 跟踪对用户是隐形的
- **切换关联**：关联态下点另一条草稿的 ⇤ → 自动暂存当前内容后切换到新关联
- **解除关联**：点标记上的取消按钮，或发送消息后，回到无关联态

### 4.5 边界情况

| 场景 | 行为 |
|---|---|
| Ctrl+S，输入框为空 | 无操作 |
| Ctrl+S，无关联，内容非空 | 新增 + 清空 |
| Ctrl+S，有关联 | 更新原记录 + 清空（不新增） |
| Ctrl+Delete，无关联 | 仅清空输入框 |
| Ctrl+Delete，有关联 | 清空 + 删除原记录 |
| 回填时输入框已有内容 | 先自动暂存再回填 |
| 发送关联中的草稿 | 消息发出，条目保留，关联解除 |
| localStorage 损坏 | 重置为空数组，不崩溃 |

## 5. 技术实现要点（对接现有代码）

- 输入框组件：`components/ChatInput.tsx`（现有 Enter 发送逻辑处增加 keydown 处理，`sendShortcut` 附近）
- 列表渲染位置：ChatWindow 中 `chatInputElement` 上方（消息列表与输入框之间）
- 存储封装：新增独立模块（如 `lib/draft-stash.ts`），读写 localStorage；注意 Next.js 服务端/客户端边界（仅客户端使用）
- 时间戳显示：相对时间格式化（无第三方依赖，手写小型格式化）
- 图标：回填 ⇤、删除 ✕、关联标记 ✎，用现有图标体系（不新增依赖）
- 毛玻璃：复用 `--glass-bg` / `--glass-blur` 变量

## 6. 不做的事（YAGNI）

- 不分类、不打标签、不搜索
- 不拖拽排序
- 不自动删除/过期/归档
- 不做多条合并回填
- 不区分草稿/想法/待办类型
- 不新增 toast 提示（Ctrl+S 是显式动作，无需反馈；回填自动暂存也不提示）
