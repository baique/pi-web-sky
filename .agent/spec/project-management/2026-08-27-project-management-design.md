## 0. 背景与目标

现状的"项目选择"是**目录下拉**：选一个文件夹就当项目。工作目录变多后下拉冗余（对应 agegr/pi-web#620 的清理诉求），且"文件夹=项目"把**实现细节（路径）当成了组织本体**。

目标：在 pi-web 内设计一层**项目管理机制**，不搬离 pi-web（功能仍在其中），但作为**设计上独立**的一层，能统一管理 **项目 → 任务 → 会话 → 临时会话** 四个层级，且随 pi 设计顺势而为、改动可控、交互与观感达到产品水准。

**核心判断（脑暴结论）**：目录 ≠ 项目。目录是物理事实，项目是逻辑组织单元。二者解耦是本设计的地基。

## 1. 核心决策（12 条，全部经脑暴确认）

| # | 决策 | 内容 |
|---|------|------|
| 1 | **项目 = 纯逻辑实体** | 用户创建/命名；**不绑定任何目录**；只是组织的容器 |
| 2 | **目录完全独立** | 走 pi 现状选择器；管"文件落哪"，不管"会话归谁" |
| 3 | **任务 = 可选分组** | 项目下的可选分组节点，聚合"同一件事"的多个会话（设计/开发各开会话、上下文满了新开）；会话可不挂任务、平铺在项目下 |
| 4 | **临时会话 = 一种状态** | 未挂任务/未归档的会话即为临时会话，非特殊类型；**不可自动删除、不干扰主线**，随时可归档转正 |
| 5 | **侧边栏布局** | 自上而下：顶栏（搜索+开聊）→ 项目树（主体）→ 临时会话区（底部折叠）→ 文件浏览器（最底部可折叠） |
| 6 | **文件浏览器** | 保留侧边栏最底部、可折叠；**与临时会话区之间高度可调**（resizable）；**无选中会话时隐藏** |
| 7 | **拖拽两级落点** | 拖会话到「项目」= 归档进项目（不挂任务）；拖到「任务」= 挂该任务 |
| 8 | **落点反馈** | 节点 accent 高亮 + **顶部横向插入线**（accent 2.5px） |
| 9 | **会话行按钮 = 方案 1** | 标题优先：悬停只浮现「展开分支」；编辑 / 移动 / 删除收进 ⋯ 溢出菜单 |
| 10 | **移动双路径** | 拖拽为主；⋯ 菜单"移动到项目/任务"为兜底 |
| 11 | **归属 = 元数据，文件不迁移** | 归档只写归属元数据；`.jsonl` 文件原地不动（pi 无会话迁移命令，移动会破坏引用） |
| 12 | **索引 = 嵌入式 SQLite FTS5** | 磁盘倒排索引（全文检索必上数据库、不放内存）；生命周期见 §6 |

## 2. 领域模型

```
项目 Project（纯逻辑实体，用户创建/命名）
 ├─ 任务 Task（可选分组节点）
 │    └─ 会话 Session（挂该任务）
 └─ 会话 Session（未挂任务 → 平铺在项目下）

临时会话（未归属任何项目的会话的聚合视图，非特殊类型）
├─ 会话的目录 = 物理事实（pi 硬约束：会话必须有 cwd，按目录落盘）
└─ 会话的项目/任务归属 = 逻辑事实（旁路元数据，可随时改）

归属解析顺序：
  1. 元数据存在 project_id  → 该项目下（有 task_id → 该任务；无 → 平铺项目）
  2. 否则                    → 临时会话区
```

**目录与归属解耦**：pi 会话文件按 `sessions/<encoded-cwd>/<ts>_<id>.jsonl` 落盘；cwd 决定文件在哪。项目/任务归属存旁路元数据，与路径无关。临时会话物理落在 scratch 目录，归档进项目后文件仍原地，仅元数据写入。

## 3. 数据层架构（与 pi 的边界）

```
pi（作者，不动）                        pi-web 数据层（新增，单一真相源）
~/.pi/agent/sessions/*.jsonl  ──增量同步──▶ SQLite 库（~/.pi/agent/ 下）
  会话文件仍由 pi 读写                       ├─ 项目管理元数据：projects / tasks / session_meta
  管道不动、格式不入侵                        └─ 全文索引：FTS5（title + firstMessage + 正文）
```

- **引入嵌入式 SQLite，不引入服务**。选型实现时定：`node:sqlite`（Node v22 内置，零依赖但需验证成熟度/flag）或 `better-sqlite3`（native、成熟）。FTS5 必须可用。
- **一个库、一个真相源**：项目管理元数据与全文索引同库（单文件），消除"文件管归属、DB 管索引"的双真相。
- **pi-web 是纯 UI/薄服务、无数据库**（现状事实）：数据层以服务端 API 路由暴露，前端只消费接口，不直接摸 SQLite。

### 3.1 Schema 草案

```sql
CREATE TABLE projects (
  id TEXT PRIMARY KEY, name TEXT NOT NULL, created INTEGER NOT NULL
);
CREATE TABLE tasks (
  id TEXT PRIMARY KEY, project_id TEXT NOT NULL REFERENCES projects(id),
  name TEXT NOT NULL, created INTEGER NOT NULL
);
CREATE TABLE session_meta (          -- 旁路归属（不碰 .jsonl）
  session_id TEXT PRIMARY KEY,
  project_id TEXT REFERENCES projects(id),
  task_id    TEXT REFERENCES tasks(id),
  updated    INTEGER NOT NULL
);
-- FTS5 虚拟表 + 映射表（见 §6）
```

### 3.2 API（草案）

- `GET /api/projects` · `POST /api/projects` · `PATCH/DELETE /api/projects/:id`
- `POST /api/projects/:id/tasks`（含改名/删除）
- `PATCH /api/sessions/:id/meta`（归档/移动归属：`{projectId?, taskId?}`）
- `GET /api/search?q=`（FTS 检索，见 §6）

## 4. 侧边栏 UI 规范

### 4.1 布局（自上而下）

```
┌─────────────────────────────┐
│ 🔍 搜索会话…        ＋ 开聊 │   ← 顶栏（chrome）
├─────────────────────────────┤
│ 📁 项目 A                   │
│  └ 🗂 任务 · 重构登录        │   ← 项目树（主体，flex 1）
│     ├ 💬 设计接口            │
│     └ 💬 实现               │
│  └ 💬 会话（平铺）           │
│ 📁 项目 B                   │
├─────────────────────────────┤
│ ⌄ 临时会话 (3)            │   ← 临时会话区（底部折叠，可调高）
│    💬 问天气                │
├──────╌╌╌ resizable ╌╌─────┤
│ ▾ 文件浏览器       2 变更  │   ← 文件浏览器（最底部，可折叠）
│    📄 src/ …               │
└─────────────────────────────┘
```

- **顶栏**：搜索框 + 「＋ 开聊」。「开聊」= 直接开临时会话，零门槛（目录自动落 `~/pi-cwd-<YYYYMMDD>`，已存在机制）。
- **项目树**：项目 → 任务 → 会话；未挂任务会话平铺项目下；会话行按钮 = 方案 1（§5.3）。
- **临时会话区**：聚合所有未归属会话；折叠可展开；不干扰主线、不自动删除。
- **文件浏览器**：沿用现状（可折叠、刷新/上传/变更计数）；**无选中会话（无 cwd）时隐藏**；与临时会话区之间 resizable（复用 `useResizablePanel`，高度持久化 localStorage）。

### 4.2 玻璃规范映射（正式开发唯一依据）

| 元素 | 层 | 配方 |
|------|----|------|
| 侧栏容器 / 顶栏 | chrome | `--side-panel` / `--frame-glass` + `blur(var(--glass-blur-heavy)) saturate(var(--glass-saturate))`（现状已统一，沿用） |
| 顶栏搜索框 | chrome 内嵌输入 | `--glass-bg-input` + `--glass-blur`（引 token，不写死 rgba/px） |
| ⋯ 菜单 / 「+」新建菜单 / 移动目标选择 | popover | `.glass-popover`（`--glass-bg-strong` 60% mix + `--glass-blur-popover`） |
| 拖拽落点高亮 | 状态色 | 引用 `--accent`（10% 底 + 描边 + 顶部 2.5px 插入线）；**不写死 rgba/px** |
| 列表行 hover | 表面 | `--bg-hover`（项目现有 token） |
| resizable 分隔条 | 骨架 | `--border`（hairline），hover 时 accent |

硬约束（照 glass-standard §6）：**不嵌套 backdrop-filter**；浮层若贴顶栏 → `.glass-top-panel` + portal 到 `<body>` 锚定；一切背景/模糊引用 token（自动获得"减弱透明/高对比"降级）。

## 5. 交互规范

### 5.1 创建入口

| 入口 | 行为 |
|------|------|
| 顶栏「开聊」 | 直接临时会话，目录落 scratch（零门槛，不做任何选择） |
| 项目悬停「＋」 | 菜单：新建任务 / 新建会话 / 挂载工作目录（延后） |
| 任务悬停「＋」 | 直接新建会话并挂该任务（意图已明确，不再套菜单） |

### 5.2 目录流（新建会话必选目录 — pi 硬约束）

| 场景 | 目录 |
|------|------|
| 开聊（临时） | 自动 `~/pi-cwd-<YYYYMMDD>` |
| 项目/任务下新建 | 弹目录选择：① 建议区（该项目已有会话的目录 + 最近使用目录，**排除 scratch**）② 现状选择器完全自选 |

### 5.3 会话行按钮（方案 1）

- 默认：只看标题，空间最大化。
- 悬停：浮现「展开分支 ⑂」（高频）+ 「⋯」。
- 「⋯」菜单：编辑、移动到项目/任务、删除。移动含二级目标选择（项目 → 任务级联）。
- 拖拽为主路径；⋯ 菜单为兜底（触屏/长列表）。

### 5.4 拖拽

- 源：会话行（按住拖起，原位置虚线占位，跟随半透明浮块）。
- 落点两级：项目 = 归档（写 `project_id`，清除 `task_id`）；任务 = 挂该任务（写 `project_id + task_id`）。
- 反馈：节点 accent 高亮 + **顶部横向插入线**。
- 临时会话区本身不是落点（它是"未归档"默认态）。
- 延后 v2：Shift + 拖拽 = 先建任务再挂入。

### 5.5 状态保存

- 侧边栏展开/折叠、resizable 高度、临时会话区折叠态 → localStorage 持久化（沿用 `loadExplorerOpen/saveExplorerOpen` 模式）。

## 6. 会话检索（索引生命周期）

### 6.1 索引形态

嵌入式 SQLite FTS5 全文索引，字段：标题（name/firstMessage）+ 正文消息文本。磁盘倒排、搜索时读、内存压力小（同 GitHub Copilot 做法；参考 fast-resume：精确匹配加权 + 模糊容错）。

### 6.2 生命周期

| 事件 | 触发时机 | 行为 |
|------|---------|------|
| **全量** | 首次启动 / 库或索引缺失 / FTS schema 版本变化 / 完整性校验失败 | 后台重建（可渐进并行，UI 不阻塞） |
| **增量** | 启动时按 `mtime` 对比；运行中监听 sessions 目录（或节流轮询） | 只重解析变更/新增会话；删除的从索引移除；原子更新（删旧+加新+commit） |
| **损坏** | 打开时校验失败 | 后台**静默重建**，用户无感知 |

### 6.3 索引管理形态（不单独放外面一个菜单）

- 平时：侧边栏一个**极小状态点**（健康 / 进行中 / 异常）。
- 管理入口收进侧边栏底部**现有设置入口那排**（ModelsConfig/SkillsConfig 旁）的「数据」页：显示索引状态、重建按钮、存储占用。

### 6.4 搜索行为

- 顶栏搜索框：即时检索标题 + 正文（BM25），结果高亮命中片段；搜索时列表切换为结果视图。
- 检索范围跨项目（含临时会话）；可选按项目/任务过滤（v1 后可加）。

## 7. 实施范围与里程碑

- **M0 · 数据层**：SQLite 初始化（schema + 迁移版本）、`/api/projects`、`/api/sessions/:id/meta`、`/api/search` 骨架
- **M1 · 侧边栏重构**：项目树 + 临时会话区 + 文件浏览器（resizable / 无选中隐藏）
- **M2 · 交互**：拖拽两级落点、⋯ 菜单（移动/编辑/删除）、创建入口（开聊/项目+/任务+）、目录流建议区
- **M3 · 检索**：索引全量/增量/静默重建、搜索 UI、状态点 + 「数据」页
- **M4 · 打磨**：玻璃规范逐项核对（§4.2）、空态文案、深/浅主题 + 减弱透明/高对比目测
